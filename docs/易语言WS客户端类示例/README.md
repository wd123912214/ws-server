# 易语言 WebSocket 客户端类示例

本示例依据`框架例子.挂机定时心跳和掉线自动重连演示.版本3.zip`中的鱼刺 HWA 客户端接口编写，无 UI，适合放入本地中控或现有客户端。

## 文件

- `WS长连接客户端.txt`：WS 类，包含握手协议头、控制帧处理、定时 Ping、掉线重连和安全停止。
- `WS客户端环境.txt`：进程级全局初始化/销毁封装。
- `无UI调用示例.txt`：最小调用方法。

把三个源码页复制进已经引用`鱼刺HWA客户端.高级（HTTPS.WebSocketSSL.Agent）`模块的工程。类源码页应建立为“类”，类名为`WS长连接客户端`；另外两个建立为普通程序集。

## 连接成功后立即断开的检查

`WS长连接客户端`对象必须声明成程序集变量或全局变量，不能声明成启动子程序的局部变量。局部类变量会在子程序返回时立刻执行`_销毁()`，随后主动关闭刚建立的连接，日志通常是`SO_CLOSE(5)`和错误代码`0`。

正确：

```text
.程序集变量 远程WS, WS长连接客户端
```

错误：

```text
.子程序 启动远程WS
.局部变量 远程WS, WS长连接客户端
```

新版诊断日志可以区分关闭来源：

- 出现`WS类对象开始销毁`：对象生命周期结束，通常是使用了局部变量。
- 出现`WS收到主动停止调用`：程序调用了`停止()`。
- 出现`WS全局环境开始销毁`：程序过早调用了`WS环境_销毁()`。
- 三条都没有但仍然断开：检查是否有另一个程序正在使用相同UID，或服务器是否正在更新白名单/重启。

## 使用顺序

1. 程序启动时只调用一次`WS环境_初始化()`。
2. 每个连接对象调用`配置()`，然后调用`启动()`。
3. 正常运行期间不需要外部定时器；服务器会主动发送 WS Ping，类负责回复 Pong。
4. 网络异常后，模块每5秒触发一次类重连回调，直到成功。
5. 程序退出前先对全部对象调用`停止()`，最后调用一次`WS环境_销毁()`。

## 心跳处理

实测确认当前HWA模块会对标准Ping自动发送未掩码Pong，严格WebSocket服务器必须按协议拒绝。因此服务器不再发送标准Ping控制帧，改为普通文本心跳：`0-heartbeat-序号`。客户端收到后使用文本帧原样回复，服务器在超时时间内收到相同序号即认为连接正常。

不要再手动发送操作码9或10，也不要修改服务器去接受未掩码帧。

新版不再调用`客户端_设置心跳()`。因为服务器已经每30秒主动检查连接，客户端再主动 Ping 属于重复心跳，还可能因为模块的设置返回值被误判为启动失败。`配置()`中的心跳间隔参数暂时保留用于兼容原调用，但当前不会创建客户端心跳定时器。

如果旧工程仍有`客户端_设置心跳()`，也应删除。`_事件_主动心跳()`只返回`#HR_OK`，不再发送操作码9。

掉线重连参数已经直接写入`客户端_连接()`的第25～29个参数，不再通过连接后的`内部_设置保活()`二次设置。

不要发送下面这种消息：

```text
客户端_发送消息体文本 (连接ID, “PONG”, ...)
```

文本`PONG`会进入服务器的业务协议解析器，因为它不符合`目标UID-txt1-txt2`，服务器会返回`0-error-INVALID_MESSAGE`。

## 中文与 UTF-8

WS 文本规范要求 UTF-8。当前服务器的UID、类型和命令通常是ASCII，可以直接使用`发送业务消息()`。如果`txt2`含中文，建议使用项目现有编码函数把完整的`目标UID-txt1-txt2`转为UTF-8字节集，再调用`发送UTF8数据()`。

接收数据保存在字节集中，可通过`取最后消息()`获得。在`内部_处理业务消息()`中使用你现有的`UTF8到文本()`转换后，再接入中控的指令处理逻辑。

## 不可调整的约束

类回调使用方法序号：连接2、断开3、接收4、主动心跳5、重连6。不要在这些回调前插入新方法，否则序号变化后可能发生错调、崩溃或无法重连。新增方法应放到`_事件_重连`之后。

同UID新连接会替换旧连接；UID必须存在于服务器`config.json`的`uid_whitelist`中。地址示例：

```text
ws://服务器IP:8080/ws
```
